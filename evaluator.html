    Eval harness for evidence retrieval

    Scoring quality is measured, not assumed. Each criterion has a golden set of events a human marked as evidence. The retriever runs over the trail, and precision and recall at k are computed against that set. Switch the candidate retriever to see a regression gate pass or fail against the shipped baseline.

    live

    Toy scale on purpose: 5 criteria over 16 events. It shows the harness shape (golden set, metric functions with their own tests, a baseline, a gate). It makes no accuracy claim about any production system. Try k=4 and k=5: on a set this small the three retrievers land close together, which is exactly why a real golden set needs far more data. In a real run the golden set is hundreds of human-scored trails, and the same gate sits in CI.

    Prompt-injection guard

    A candidate's trail, or their AI assistant's output, can contain text aimed at the grader. The guard normalizes text, runs cheap rules, decodes hidden payloads, and wraps everything as untrusted data before any model sees it. Rules are only the first layer.       Reviewer assist
      
    
      Agentic helpers for the human reviewer: summarize the trail, flag gaps, draft follow-up interview questions. Gaps are computed from the scoring above. Question drafts are templated here; in production they are an LLM call that receives the cited events, and the reviewer edits before anything is asked.
      
  
      
  
      
    
      
      
      
      
    
      
    
      
  
      

      



      
  
      
    
      Model choice, cost, latency and fallback
      
    
      Each pipeline stage gets the cheapest tier that passes its eval, with a defined fallback across providers. The calculator uses placeholder prices you can edit. Replace them with current provider rates before trusting a number.

      Failure handling: one schema-repair retry, then the next provider. Circuit breaker opens after 3 consecutive failures for 60 seconds. If every provider fails, the screen goes to a human queue with whatever partial results exist. Model, prompt version and provider are logged on every score so a regression can be traced.

      Scope and what comes next
      
  
      
    
      
      
      What this page is and is not
      
      
        
        
      • It is built from the public job post. It is not Touchstones' product, code, rubric or data, and it is not affiliated with them.
        • 
        
      • The candidate, trail and rubric are invented for this demo.
        • 
        
      • Live: citation verification, retrieval metrics and gate, the injection rules and test suite, the tool policy, gap detection, the cost model.
        • 
        
      • Recorded: the rubric scores and reasoning. A real run calls a model; this page cannot.
        • 
        
      • No biometric input exists in the data model: events are text, test runs and shell output only. No video, voice, face, eye tracking or keystroke dynamics.
        •
